# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

믓 (MOVE & STRENGTH; repo `Hnyangs/movenstrength`, formerly MasilMuscle) is a Korean-language, mobile-first (dark UI) workout management web app for regular members and trainers, backed by Supabase (Auth + Postgres). The whole frontend is a single static file, `index.html` (inline `<style>` + one inline `<script>`; `@supabase/supabase-js` is loaded from the jsdelivr CDN). There is no build system, package manager, linter, or test suite.

Other files: `supabase/schema.sql` (tables, auth trigger, RLS policies — run once in the Supabase SQL editor), `supabase/auth_trigger.sql` (the signup-profile trigger alone, idempotent), `supabase/migration_002_mypage_inbody.sql` (idempotent, run after the others: profile info columns + `trainer_code`, `workout_logs.note`, `inbody_records`, PT `requested` status, self-profile update guarded by the `guard_profile_update` trigger, and the `my_trainer_code` / `link_trainer` / `unlink_trainer` RPCs), `supabase/migration_003_inbody_fields.sql` (`inbody_records.fat_mass`, `visceral_fat`; InBody input mirrors the user's sheet: weight, muscle, fat mass, visceral level — `fat_pct` is computed on save, BMI from profile height), `supabase/migration_004_social_login.sql` (`profiles.onboarded`; signup trigger reads social metadata names and marks non-email signups `onboarded=false`; `complete_onboarding(name, role, level)` RPC, one-time), `supabase/migration_005_trainer_tools.sql` (trainer profile columns `center_name/career/specialty/bio`; `member_code` per member via trigger; `is_managed` members without accounts — drops the `profiles.id → auth.users` FK; `create_managed_member` and `search_members` (name/code/email, masked email) RPCs; trainer notes moved to `member_notes(member_id, trainer_id)` which members cannot read, profile `notes/curriculum` cleared), `supabase/migration_006_sheet_import.sql` (`workout_logs.imported`; trainers may insert PT or `imported` rows for their own members), `supabase/migration_007_edit_consent_withdraw.sql` (`logs_update` policy + `guard_log_update` trigger keeping `user_id/is_pt/imported` fixed; consent columns `terms_agreed_at/under14/guardian_agreed`, signup trigger reads `terms_agreed/under14/guardian_agreed` metadata, `agree_terms(p_under14, p_guardian)` RPC; `delete_my_account()` RPC deleting the profile (cascading records), the caller's managed members and the `auth.users` row), `supabase/migration_008_level_names.sql` (level check constraint now allows 스타터/루티너/빌더/마스터/믓쟁이 besides the legacy values and renames earlier tier-name rows), `supabase/migration_009_account_cleanup.sql` (trigger on `auth.users` delete removes the profile, the trainer's PT rows and managed members — needed because 005 dropped the profiles→auth.users FK; `delete_my_account` also deletes PT rows explicitly), `supabase/exercises.sql` (idempotent: `exercises` table + RLS + seed of ~376 exercises, and drops the `workout_logs.part` check) and `.github/workflows/keep-supabase-alive.yml` (daily 09:00 KST GET to the REST API; needs `SUPABASE_URL` and `SUPABASE_ANON_KEY` repo secrets).

## Brand (믓 · MOVE & STRENGTH)

The app is branded **믓** (`MasilMuscle` is the legacy name and appears only in old history). `brand/README.md` is the design system: logo symbol (the exact Pretendard Black "믓" glyph outline as an SVG path — never redraw it or add marks; ㅡ is filled with the accent, ㅁ·ㅅ chalk/iron; SVGs in `brand/`, inline copy in `logoSvg()`), colors (IRON BLACK #171717, CHALK WHITE #F2F0E9, FIELD GREEN #B5C49C = workout state, PULSE TEAL #4FB3A0 = accent/primary action (`--accent`; replaced rust orange); warnings use mustard `--warn` #D9A05B, CONCRETE #77736D, GRAPHITE #333333; ratio 55/30/10/5), type (Pretendard + IBM Plex Mono for short English labels/numbers only), sizes (20px gutter, 8px grid, 6px radius, 4px chips, 48–52px controls) and copy tone (e.g. 저장 → "오늘도 한 건 했다.", new best weight → "오, 이건 좀 믓지다."). In `index.html` use the role tokens (`--bg --card --card2 --line --t --m --p`) rather than raw hex; `.card.hl` is the chalk-white highlight card that re-scopes those tokens for dark-on-light. UI uses inline 2px line icons (`ICON`/`ico()`), not emoji. Secondary text must be `--m` (#9A958D), since CONCRETE fails contrast for small text.

No build step. Serve statically (e.g. `python3 -m http.server`) and view at mobile width (`max-width:480px`). `SUPABASE_URL` at the top of the script is the project base URL (`https://<project-ref>.supabase.co`, no `/rest/v1/` suffix; the auth screen warns if it is the bare `supabase.co`). ## Architecture

Vanilla JS, no framework or modules; order in the `<script>`: config → domain constants → state/utils → auth → data loading → recommendation → views → `render()`.

- **State**: one in-memory object `st` (`me` profile, `tab`, `mode`, `members`, `sel` selected member, `logs`, `pts`, `draft` record form, ...). Nothing is persisted locally; the Supabase session is persisted by supabase-js. Pattern: call a Supabase mutation through `ok(await sb...)` inside `run(...)` (toasts errors), then `loadData()` and `render()`.
- **UI state persistence**: `saveUi()` writes the current tab, mode, selected member, record `draft`, routine, history filters, week/PT view and scroll to localStorage `mm-ui` (on every `render()`, debounced on input, on `visibilitychange`/`pagehide`); `boot()` calls `restoreUi()` after a restored session (not after a fresh/OAuth login, which starts at 홈) when the saved uid matches and it is under 24h old. `logout()` clears it. Date-relative state is not restored as-is: the home week offset always resets to this week and `ptDate` is restored only on the same calendar day. Any new piece of screen state that should survive leaving the app must be added to both functions.
- **Rendering**: `render()` rebuilds `#app` innerHTML from template strings. Handlers are inline `onclick`/`onchange`, so they must stay global. Always wrap user text in `esc()`. Form inputs update `st.draft` via `oninput` without re-rendering (to keep focus); steppers/chips re-render.
- **Roles & modes**: `profiles.role` is `member` or `trainer`. A trainer has two modes (`st.mode`): `trainer` (`coaching()` true: home/members/record/pt/my tabs, acting on the selected member `st.sel`) and `personal` (same screens as a member, on their own data). `targetId()`/`targetProfile()` resolve whose data the current screen reads/writes; records created while coaching get `is_pt: true`.
- **Exercise catalog**: body parts (`PARTS`, 11 values from the CSV: 전신, 하체, 등, 가슴, 어깨, 이두, 삼두, 복근_신전근, 필라테스, 애니멀플로우, BASIC) and their exercises come from the Supabase `exercises(body_part, name)` table, loaded into `st.exercises` by `loadExercises()` at login; `exercisesOf(part)` merges it with exercises already in the user's logs. Saving a log with a name not in the catalog upserts it into `exercises` (ignore duplicates). `workout_logs.part` stores the body_part value; legacy `팔` logs still count toward 이두/삼두 rest days.
- **Data model** (see `supabase/schema.sql`): `profiles` (role, level 초급/중급/고급, `trainer_id`, `notes`, `curriculum`), `workout_logs` (`user_id`, `log_date`, `part`, `exercise`, `sets` jsonb `[{w,r}]`, `feedback`, `is_pt`), `pt_schedules` (`member_id`, `trainer_id`, `pt_date`, `pt_time`, `goal`, `status` scheduled/completed/canceled). A DB trigger creates the `profiles` row from signup metadata (`name`, `role`, `level`); the client only inserts a fallback profile if it is missing. Changing columns/policies means updating both `schema.sql` and the client queries.
- **RLS drives the trainer features**: trainers can read member profiles (to look up by exact email) and claim only unassigned members (`trainer_id` null → self); trainers can read/insert/delete logs and manage PT rows only for their own members; members can read their trainer's profile. Policies use `security definer` helpers (`is_trainer`, `my_trainer_id`, `is_my_member`) to avoid recursion.
- **UI identity (keep it distinct from Rappo-style apps)**: header shows only the logo + mono `MOVE & STRENGTH` wordmark (no name/level). Member nav order is 홈 · 인바디 · 기록 · 수업 · 마이, all tabs styled alike (active = chalk label + teal icon). The record form's 저장하기 sits in a fixed `.savebar` above the nav and starts with one set. The look is an editorial "운동일지 포스터": the last CSS block overrides cards to hairline-separated sections (no boxes/rounded cards), underline inputs, 2px radius, mono labels, and a single full-bleed chalk slab (`.card.hl`) per screen. Home = state headline (오늘 한 건 했다. / 쇠가 기다린다. …) → `.hero` (giant 연속 일 number via `streak()`, 이번 주 `weekDays()`, 마지막 운동) → week strip where worked-out days are filled field-green cells (today = teal ring; PT/인바디 dots remain) → chalk recommendation card → PT card. The record form has an 종목 검색 box (`exSearch` → `exPick` selects part+exercise across all parts; `exAdd` applies a typed unknown name as the custom exercise of the current draft, and `saveLog()` then registers it in the catalog). The record form shows the last session's values as input placeholders and a "지난번 그대로 채우기" button (`fillLast()`).
- **Tabs**: member/personal mode = 홈(weekly calendar strip with 운동/PT/인바디 dots; tapping a day filters history by `st.hf.date`) · 인바디 · 기록 · 수업 (members only: PT request/cancel, upcoming PT, PT logs with trainer feedback/note, filterable by body part via `st.classPart` / `classPartSet()`) · 마이 (운동 기록 entry → the `history` screen, which is not a bottom tab here: `SUB_TABS` maps it to 마이 for nav highlighting and it shows a ‹ 마이 back link; 운동 등급 card `levelCard()`; 내 정보; trainer-code linking; 회원 탈퇴 sheet `withdrawSheet()` → `delete_my_account`). There is no font-size setting anymore. Week strip and PT nav use `navBtn()` and horizontal swipe on `[data-swipe]` areas (`SWIPE` map). Coaching mode = 홈 (today's PT across all members + upcoming, quick 수업 기록하기 / 완료 처리) · 회원 (PT requests to approve, search, register, sheet import; the selected member card has 운동 기록 / 인바디 shortcuts that open the `history` / `inbody` screens, which `SUB_TABS()` highlights under 회원 and which show a ‹ 회원 back link) · 기록 · PT (schedule for all members, day/week via `st.ptMode`, default day; `+ PT 일정 등록` opens a bottom sheet `ptSheet()` with member/date/time/goal) · 마이 (shows the trainer's 4-digit code). `st.trainerPT` holds all of the trainer's PT rows (every member/status).
- **Social login**: Kakao and Google via `sb.auth.signInWithOAuth` (`oauth(provider)`, redirect back to the same page; OAuth errors in the URL are toasted and the URL is cleaned in `boot()`). Naver is not a built-in Supabase provider, so it goes through the Edge Function `supabase/functions/naver-auth` (deploy with `--no-verify-jwt`; secrets `NAVER_CLIENT_ID`/`NAVER_CLIENT_SECRET`): `start` returns the Naver authorize URL, the app stores a random `state` in sessionStorage, and on return `boot()` posts `callback` only when `state` matches, then `sb.auth.setSession()` with the returned tokens. The function keys Naver users by an internal email `naver_<id>@naver.invalid` (never merged by the Naver contact email, which is unverified) and marks new profiles `onboarded=false`. OAuth redirect target is `appUrl()` (path without `index.html`), which must match the Naver callback URL exactly. A profile with `onboarded === false` renders `onboardView()` (name, role, consent; no level) instead of the app until `complete_onboarding` succeeds.
- **Trainer tools (005)**: members tab searches via `search_members` and can create managed members (`addManaged`); member labels use `mLabel()` (name · member code). Trainer notes load into `st.mnote` from `member_notes` (`st.notesTable`; falls back to profile columns before the migration) and are never shown to members — the member home card shows only the PT schedule. Trainers have no level in signup/onboarding/My (stored as 고급); their My page edits the trainer profile, which members see via `trainerCard()`.
- **PT status colors**: `ptTag()` / `.st-<status>` — 예정 orange (`--plan`), 완료 green, 신청 teal. Calendar dots: 운동 chalk, PT 완료 green, PT 예정 orange, 인바디 teal.
- **Recommended routine**: "추천 운동으로 시작하기" → `startRoutine()` stores `st.routine`; `loadItem()` prefills reps only (weight is typed in); saving advances to the next item. Sets per exercise are unlimited.
- **Sheet import**: members tab → "구글 시트 기록 가져오기" (`parseSheet` → `impPlan` → `runImport`). Upload the Google Sheet CSV (header row found by `Date`+`Exercise`; `Work`, `w1..wN`/`r1..rN`, `pt`, `Feedback`, `Note`; optional `member_code`/`회원코드` column). Rows map to a member by member code (the typed code, or per-row code) among `st.members`; only the trainer's own members are accepted. Non-numeric weights become 0kg with a `[무게메모: …]` note, rows without reps are skipped, identical `date|exercise|sets` rows are skipped (re-uploading is safe), rows insert in chunks of 300 with `imported:true`, and new exercises are added to the catalog.
- **Trainer linking**: a member links by entering the trainer's 4-digit code (`link_trainer` RPC); trainers can also claim members by email. Members cannot change `role`/`trainer_id`/`notes`/`curriculum`/`trainer_code` on their own row (trigger reverts them; RPCs bypass via `app.bypass_guard`). If the migration has not been run, `st.needMig` shows a hint and the app degrades (no inbody, note only sent when non-empty).
- **Login screen**: email login/signup is collapsed under "또는 이메일로" (`st.emailOpen`; opened by default only if the last login was email). The last method is stored in localStorage `mm-last-login` (set on email login, or via sessionStorage `mm-pending-login` when an OAuth redirect returns with a session) and shown as a "최근 로그인" badge. Login is always kept (supabase-js default localStorage, no toggle); `boot()` signs out when `mm-login-at` (last real login) is older than `KEEP_DAYS` (30).
- **운동 등급 (level)**: never asked at signup. `levelFromLogs()` derives it from logs via `LEVEL_RULES` (5 tiers 스타터 → 루티너 (≥90 days, ≥36 distinct log days) → 빌더 (≥1y, ≥150) → 마스터 (≥3y, ≥500) → 믓쟁이 (≥5y, ≥900), each with a one-line tagline; span = days since first log); `curLevel()` is the tier name, `planLevel()` maps it via `PLAN_KEY` to the 3-level 초급/중급/고급 used by `PLANS`/`TARGET_REPS`. `loadData()` syncs the tier into `profiles.level` for members (trainer lists/search); legacy stored values (초급/중급/고급 and earlier tier names) are shown via `levelName()`; `migration_008` widens the level check constraint. Trainers are stored as 고급.
- **Recommendation engine** (`recommend`, `suggest`, `topExercises`): split per level in `PLANS` (초급 상체/하체, or 전신 when no logs; 중급 밀기/당기기/하체; 고급 4분할). Picks the group whose most recently trained part rested longest. Progressive overload per exercise from the latest log: all sets ≥ `TARGET_REPS[level]` (12/10/8) → weight +2.5kg (≥40kg) or +1kg (bodyweight → +1 rep); otherwise same weight, +1 rep. A latest log per part whose feedback matches `통증|부상` triggers a warning card.
- **Large reads**: Supabase returns at most 1000 rows per request, so lists that can exceed that (`workout_logs`, `exercises`) are loaded with `fetchAll(() => query)`, which pages with `.range()`. Keep a stable `.order()` (with `id` as tiebreaker) on such queries.
- **History search**: the history tab filters the already-loaded `st.logs` client-side via `st.hf` (text query over exercise/feedback, body-part chips, exercise dropdown); picking an exercise shows a summary (count, best set, last date), a per-set-number min/max weight table (like the sheet's "운동별 최대/최소 무게") and a compact date | kg×reps table of every past session. Feedback is collapsed by default (💬 toggle); the date sort toggle (`st.hf.sort`) reverses the newest-first `st.logs`. Members cannot edit or delete trainer-made PT logs (`canEdit`/`canDelete`; the class tab shows none). 수정/삭제 buttons only appear while "편집 모드" (`st.hf.edit`) is on, to prevent mis-taps. 수정 (`editLog`, only if `canEdit(l)`: members their non-PT logs, trainers their members' PT/imported logs) loads the log into `st.draft` with its `id`; the record screen then shows "기록 수정" and `saveLog()` updates instead of inserting. The record tab shows the last 3 records of the chosen exercise.
- **Dates**: use `today()` / `localDate()` (timezone-corrected `YYYY-MM-DD`), not `toISOString()` directly.
